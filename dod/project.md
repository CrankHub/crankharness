# Project-level definition of done

Verbatim from the harness plan (Nov 2, 2026). The review unit is a Linear project, not a release, a milestone or a
cycle (Rob, Nov 2, 2026). It is the one human checkpoint: nothing before it waits on Rob.

```text
Project-level definition of done: the single human review (Trey, Nov 2, 2026)

Triggered when every issue in the Linear project is Done or Blocked.
Evidence bundle, generated by the orchestrator from run folders:
1. Changelog: user-facing summary of every issue in the project.
2. PR list with links, author and reviewer models, and review verdicts.
3. Test results on main: unit, e2e, and the coverage trend vs. project start.
4. Flagged items: high-risk merges (auth, security, migrations, destructive),
   retries, stop conditions hit, escalations, reverts, flaky tests.
5. Eval results for any agent skills or prompts changed in this project.
6. Open issues: anything not Done, plus bugs filed during the project.
7. Usage: turns, wall time, and usage-limit pauses per issue (no dollar figures).
8. Summary of FOR_ROB_TO_CONFIRM.md: checked vs. unchecked items.

Decision (Trey, once per project):
- Accept: close the project.
- Findings: file them as new issues (label from-rob) in the project; agents
  pick them up like any other issue. Nothing merged is reverted automatically.
```

The bundle generator is ROB-416; the first review end to end is ROB-418 (Phase 3b). Until then a project that
reaches "every issue Done or Blocked" is reviewed from its PR list and `FOR_ROB_TO_CONFIRM.md` by hand, and the PR
that closes the last issue says so.
